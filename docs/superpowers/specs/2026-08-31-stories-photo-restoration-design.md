# Stories 真实评论图片恢复设计

日期：2026-08-31

状态：已完成视觉方案确认，待文档审阅

## 目标

恢复 Stories 页面中已存在且可核验的真实评论图片，使客户评价在不误配人物照片的前提下更易阅读和识别。

## 范围

### 包含

- 将 `public/stories/` 中 4 张已有照片与 Stories 数据中同名评论严格绑定。
- 在每张匹配图片的评价卡顶部显示照片，并在作者行展示同一图片的缩略头像。
- 保留原有评论、产品名称、筛选标签和滚动动画。
- 对没有可核验图片的评论继续显示姓名首字母头像。
- 删除精选故事区域内 `Eleanor 1` 和 `Eleanor 2` 的伪图片占位，改为不暗示存在真实人物照片的内容布局。

### 不包含

- 不抓取 Amazon、社交媒体或任何第三方网站的用户照片。
- 不生成、修改或替换人物照片。
- 不将现有照片用于不同姓名的评价。
- 不新增后端、数据库、上传入口或评论审核流程。

## 数据模型与匹配规则

在 Stories 数据记录中增加可选字段 `image`。该字段只接受以 `/stories/` 开头的项目内静态路径；没有字段则代表该评价没有已授权或可核验图片。

首批允许的映射是：

| 评论作者 | 图片路径 |
| --- | --- |
| Hadji Reyes | `/stories/Hadji Reyes.jpg` |
| Eddy Simon | `/stories/Eddy Simon.jpg` |
| Michele Guess | `/stories/Michele Guess.jpg` |
| SmashOhh | `/stories/SmashOhh.jpg` |

Stephanie Freeman、Stacy Olney、Lisa Sullivan 和 Kimberly Bryant 没有对应图片字段。页面必须保持首字母头像，不能通过名称相似、产品相同或视觉推断来选择照片。

## 页面呈现

每个有图片的评价卡使用固定 `4:3` 媒体区域，照片采用 `object-fit: cover`，在桌面、平板和手机上保持稳定的卡片高度。图片的 `alt` 文本描述作者和 GoldSeason 轮椅，缩略头像使用空 `alt`，避免重复朗读。

无图片评价卡仍为完整的文字卡，不预留空白图片区域。其作者行使用当前的姓名首字母圆形头像，因此用户不会将缺图理解为加载错误。

精选故事的“Eleanor”没有项目内可核验照片。该区域不再渲染 `Eleanor 1` 或 `Eleanor 2` 文字占位，而是以引语和作者信息为主；在取得可用来源前不显示人物图像。

## 实现边界

- 修改仅限 `src/app/stories/page.tsx` 与该页面新增的测试文件。
- 复用现有 Tailwind 风格、`RevealOnScroll` 和 `HoverScale` 组件，不引入新的图片服务或依赖。
- 使用原生 `<img>`，与网站其他本地静态图片的现有做法一致；路径中的空格由浏览器编码处理。
- 图片加载失败时，图片容器应自动退化为首字母头像，不暴露损坏图片图标或空白卡片。

## 测试与验收

新增页面测试并先观察失败，覆盖以下行为：

1. 四位有匹配图片的作者渲染正确的图片路径和描述性替代文本。
2. 无图片作者不渲染内容照片，仍可看见姓名首字母头像与评论内容。
3. 页面不再渲染 `Eleanor 1` 或 `Eleanor 2` 占位文字。
4. 图片的加载错误会切换到无图片降级状态。

实现后运行 Stories 页面测试、全量 Vitest、TypeScript 检查和生产构建，并用浏览器在桌面及手机宽度检查图片裁切、长评论和键盘可读性。

## 验收标准

- 四张现有真实评论照片只与同名评价绑定。
- 其余四条评价不显示人物照片，且没有空白媒体区域。
- 精选故事不再伪装成已有两张 Eleanor 照片。
- 所有实际显示的照片有有意义的替代文本。
- 图片失败时，页面仍然可读且不会把另一位客户的图片作为回退。
