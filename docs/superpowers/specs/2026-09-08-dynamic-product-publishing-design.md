# 动态产品发布、规格、SKU 与配件设计

日期：2026-09-08

状态：用户已确认，进入实施计划

## 1. 目标

扩展现有 GoldSeason 管理后台，使管理员无需修改代码或重新部署即可：

1. 新增、编辑、排序和停用产品品类。
2. 为每个品类维护可复用的规格模板。
3. 在一个产品下管理多个 SKU/变体及其差异化规格、价格和购买链接。
4. 同时维护包装内含物与可单独购买的兼容配件。
5. 为电动轮椅和手动轮椅保存足以支持自动推荐的结构化资料。
6. 发布后让商品目录、产品详情和 Wheelchair Finder 立即读取同一份数据。

首批内置品类为 `Powered Wheelchair`、`Manual Wheelchair`、`Mobility Scooter`、`Shower Chair` 和通用配件品类。管理员可以继续创建产品类或配件类品类。

## 2. 已确认的核心决策

- 采用关系数据与动态规格相结合的混合结构。
- 品类、SKU、包装内含物和配件关系使用关系表；产品和 SKU 的动态规格值使用经过模板校验的结构化 JSON。
- 规格模板提供系统预设字段，并允许管理员增加普通字段。
- 推荐器依赖的字段使用受保护的系统语义，不允许删除、改变数据类型或重新解释含义。
- 一个产品可以有多个 SKU。产品层保存默认价格、原价和购买链接；SKU 可以按需覆盖。
- 包装内含物是产品下的名称、数量、备注列表。
- 兼容配件是独立发布的配件商品，兼容关系按整个产品维护，不细分到 SKU。
- 电动轮椅和手动轮椅发布后自动进入对应推荐流程；缺少推荐必需数据时阻止发布。
- 代步车、淋浴椅和普通配件首期只进入商品目录，不进入 Wheelchair Finder。
- 面向美国顾客的前台默认显示英制。后台可以按英制或公制录入，系统换算为规范值后保存。

## 3. 领域模型

### 3.1 ProductCategory

产品品类保存：

- `id`、`name`、`slug`、`description`
- `role`：`PRODUCT` 或 `ACCESSORY`
- `recommendationProfile`：`POWERED_WHEELCHAIR`、`MANUAL_WHEELCHAIR` 或 `NONE`
- `status`：`ACTIVE` 或 `ARCHIVED`
- `sortOrder`、`templateVersion`、`createdAt`、`updatedAt`

规则：

- `slug` 全局唯一，用于稳定 URL 和筛选，不随展示名称修改而自动变化。
- 选择电动或手动轮椅推荐配置时，系统自动加入该配置所需的受保护规格字段。
- 已被产品使用的品类不能硬删除，只能归档。归档品类不能用于新产品，但历史产品仍可读取。
- 新建自定义品类默认使用 `NONE` 推荐配置，避免普通产品误入轮椅推荐。

### 3.2 SpecificationField

每个品类的规格模板由若干字段定义组成：

- `id`、`categoryId`、`key`、`label`、`group`
- `scope`：`PRODUCT` 或 `VARIANT`
- `dataType`：`TEXT`、`NUMBER`、`BOOLEAN`、`SELECT` 或 `DIMENSIONS`
- `unitFamily`：无单位、长度、重量、距离、速度、功率、电压、电量、容量或角度
- `defaultDisplayUnit`、`options`、`helpText`
- `requiredForPublish`、`requiredForRecommendation`
- `semanticKey`、`isProtected`、`status`、`sortOrder`

普通展示字段的 `semanticKey` 为空。承重、有效座宽等机器判定字段具有稳定 `semanticKey`，推荐器只按该语义键取值，不依赖管理员可修改的展示名称。

受保护字段允许修改展示名称、帮助文字和顺序，但不能删除、停用、改变类型、改变单位族或改绑语义。已使用的普通字段也采用停用而非删除。

新增字段先默认为非必填。只有当所有已发布产品均有有效值时，管理员才能把它改为发布或推荐必填，避免模板变化突然破坏线上产品。

### 3.3 Product

保留现有产品的名称、型号族、文案、价格、链接、图片、精选、排序和发布状态，并作以下调整：

- 使用 `categoryId` 关联 `ProductCategory`，逐步替代自由文本 `category`。
- 产品层保存默认 `price`、`originalPrice`、`amazonLink`。
- 产品层 `specifications` 保存对所有 SKU 共用、且模板范围为 `PRODUCT` 的规格值。
- 关联多个 `ProductVariant`、`ProductInBoxItem` 和兼容配件。
- 继续使用现有 `ProductImage` 与 Vercel Blob 图片流程。

产品规格 JSON 以字段 `key` 为索引。每个值保存规范值、原始录入单位、明确的资料状态和可选来源备注。资料状态至少包括 `PROVIDED`、`NOT_PROVIDED` 和 `CONFLICTING`。系统不得用估算值替换缺失或冲突的官方数据。

### 3.4 ProductVariant

每个产品至少需要一个有效 SKU 才能发布。SKU 保存：

- `id`、`productId`、`sku`、`factoryModel`、`label`
- 颜色或配置说明
- 可选 `priceOverride`、`originalPriceOverride`、`purchaseLinkOverride`
- `specifications`、`isActive`、`sortOrder`
- `createdAt`、`updatedAt`

`sku` 全局唯一。没有覆盖值时，前台继承产品层价格、原价和购买链接。停用 SKU 不再供顾客选择，也不进入推荐；产品至少保留一个有效 SKU。

### 3.5 ProductInBoxItem

包装内含物保存 `productId`、`name`、`quantity`、`note` 和 `sortOrder`。它不是可购买商品，不要求关联配件记录。

### 3.6 ProductAccessory

兼容配件使用产品到配件商品的有向关系：

- `productId` 指向主体产品。
- `accessoryProductId` 指向品类角色为 `ACCESSORY` 的产品。
- 同一关系唯一，禁止产品关联自身。
- 兼容性适用于主体产品全部 SKU。
- 删除关系不会删除配件商品；归档或下线的配件不再显示在前台。

## 4. 默认规格模板

### 4.1 电动轮椅

默认分为四组：

1. 适配与坐姿：最大承重、有效座宽、座深、座高、座面到脚踏的垂直距离、坐垫宽深、扶手内距。
2. 尺寸与运输：整车长宽高、折叠长宽高、不含电池净重、电池重量、转弯半径。
3. 性能与车轮：续航、最高速度、越障高度、前后轮尺寸、轮胎类型、电机功率。
4. 电池：化学类型、是否可拆、额定电压、容量 Ah、制造商航空运输说明。

系统根据重量和电池是否可拆计算最重搬运重量，根据电压与 Ah 计算 Wh。任一输入缺失或冲突时不计算结果。

### 4.2 手动轮椅

默认分为三组：

1. 适配与坐姿：最大承重、有效座宽、座深、座高、座面到脚踏的垂直距离、扶手内距。
2. 尺寸与运输：整车长宽高、折叠长宽高、产品重量、最重可拆部件、折叠方式。
3. 移动配置：自推式或运输式、前后轮尺寸、轮胎类型、刹车类型、扶手类型和脚踏类型。

### 4.3 代步车

默认分为三组：

1. 适配与承重：最大承重、座宽、座深、座高、座椅类型、车把是否可调。
2. 尺寸与运输：整车长宽高、折叠或拆分尺寸、总重量、最重部件、转弯半径、离地间隙。
3. 性能与电气：续航、最高速度、最大爬坡角、电机功率、电池类型/电压/Ah/Wh、车轮和轮胎类型。

### 4.4 淋浴椅、配件与未来品类

淋浴椅使用可扩展的基础模板，管理员可添加承重、座面尺寸、整体尺寸、调节范围、材料、防滑脚、扶手、靠背和便桶兼容性等字段。普通配件和未来品类从基础商品字段开始，由管理员增加适用规格。

## 5. 单位与数据质量

- 后台每个数值字段按其单位族提供单位选择，例如 `lb/kg`、`in/mm`、`mi/km`、`mph/km/h`。
- 默认录入和美国前台显示使用英制，但系统以稳定的规范单位保存计算值；同时保留原始录入值和单位用于复核。
- 尺寸字段使用独立的长、宽、高数值，不接受难以校验的组合自由文本。
- 字段按模板设置合理最小值和最大值，拒绝负数、非有限数值和明显超界数据。
- `NOT_PROVIDED` 与数值 `0` 严格区分。
- 来源冲突保留原始资料和备注，不静默覆盖。
- 电池航空相关数据不完整时，产品可以发布，但不得显示已通过航空运输验证，也不得在航空条件下给出无警告推荐。

## 6. 管理后台体验

### 6.1 导航

Admin 导航新增 `Product Categories`。现有 Products 页面继续负责产品列表和发布状态。

### 6.2 产品编辑器

产品编辑器分为五个页签：

1. `Overview`：名称、品类、文案、默认价格和购买链接。
2. `Specifications`：产品层共用规格，按模板分组显示。
3. `SKUs`：SKU 列表、每个 SKU 的差异化规格及价格/链接覆盖。
4. `Accessories`：`In the Box` 列表和可购买兼容配件选择器。
5. `Media`：现有产品图片上传、排序、替代文本和来源备注。

选择品类后加载相应模板。切换已填写产品的品类时，后台先显示影响预览：可映射的语义字段保留，不兼容字段留在草稿审查区，管理员确认后才切换。

保存草稿允许资料不完整。`Review & Publish` 汇总错误并提供到具体页签、SKU 和字段的链接；不会只返回笼统的“发布失败”。

### 6.3 品类与模板管理

品类列表显示角色、推荐配置、状态、产品数量和模板版本。编辑页面可新增、排序、停用普通字段，并预览产品编辑器中的实际分组。

模板发生结构变化时版本号递增。已有草稿标记为“需要复核”。受保护字段和已经有产品数据的字段不允许硬删除。

## 7. 发布校验

所有产品发布时检查：

- 品类有效且未归档。
- 名称、价格、主图等现有发布必填项有效。
- 至少一个有效 SKU，且 SKU 唯一。
- 模板要求的产品层与 SKU 层字段齐全、类型正确、单位有效。
- 兼容配件是已发布的配件类商品，无自关联或重复关系。
- SKU 覆盖价格和购买链接有效；没有覆盖时存在可继承的产品默认值。

电动和手动轮椅还必须通过推荐数据校验：

- 硬筛选必需：最大承重、有效座宽。
- 精确适配必需：座深、座高、座面到脚踏的垂直距离。
- 电动轮椅排序必需：整车宽度、折叠尺寸、不含电池净重、续航、转弯半径、越障高度、后轮尺寸和轮胎类型。
- 手动轮椅排序必需：整车与折叠尺寸、产品重量、推进类型、前后轮尺寸和轮胎类型。

电池航空数据属于条件性要求：缺失时不阻止一般场景发布，但当用户选择航空运输需求时，该 SKU 不得被当作已验证匹配，前台必须显示核实提示。

## 8. 前台数据流与展示

- 商品目录的一级品类由所有有效的产品类品类动态生成；配件类品类进入 Accessories 区域。
- 产品卡片展示该品类配置的关键摘要字段。
- 产品详情或现有详情弹层增加 SKU 选择、分组规格、`In the Box` 和 `Compatible Accessories`。
- 切换 SKU 时更新规格、价格、原价、购买链接和配置说明。
- 兼容配件卡片复用其独立商品的名称、图片、价格和链接。
- 发布、下线、品类或模板变更后使产品目录与推荐数据缓存失效，正常情况下无需重新部署。

Wheelchair Finder 首步增加动力类型选择：`Powered Wheelchair` 或 `Manual Wheelchair`。两类共用身体尺寸、安全提示、承重与有效座宽硬筛选；随后调用各自的类型评分配置。

推荐器从数据库读取已发布产品的有效 SKU，并按 `recommendationProfile` 选择候选。最大承重和有效座宽优先作为硬性排除条件。座深目标继续使用臀膝长减 50-60 mm；脚踏适配继续按“座面到脚踏的垂直距离”结合座高和小腿长计算。

数据库或推荐数据加载失败时，推荐器显示暂时不可用，不返回猜测或半完整结果。商品目录可使用最后一次成功生成的缓存；发布操作会主动刷新该缓存。现有静态产品数据只在迁移验证期间保留，完成切换后不再作为长期第二数据源。

## 9. API、权限与事务

- 新增管理员品类与模板 API，并扩展产品 API 以提交 SKU、规格、包装内含物和配件关系。
- 所有 `/api/admin/*` 路由继续在服务端调用现有 `requireAdmin()`，普通用户不可读取或修改后台数据。
- 产品发布使用数据库事务：产品、SKU、规格、内含物、配件关系和发布状态必须整体成功或整体回滚。
- 继续使用 `updatedAt` 或等效版本字段做并发检查，防止旧页面覆盖新修改。
- 图片仍通过现有 Vercel Blob 流程保存；本功能不改变媒体权限与格式规则。
- API 返回结构化字段错误，至少包含页签、SKU 标识、字段键和可读提示。

## 10. 迁移策略

采用向后兼容的分阶段迁移：

1. 先新增品类、模板、SKU、内含物和配件关系表，并为 Product 增加可空 `categoryId` 和规格 JSON。
2. 写入首批内置品类和受保护字段模板。
3. 把现有 `wheelchair`、`scooter` 产品映射到新内置品类，保留图片、价格、促销、发布状态、排序和 URL。
4. 按现有官方轮椅数据创建 SKU 与规范化规格。无法一一匹配或存在冲突的记录保持草稿或标记需要复核，不猜测填充。
5. 对迁移结果运行数量、标识、图片、价格、规格和推荐快照校验。
6. 部署兼容新旧字段的读取代码，验证生产数据后再把 `categoryId` 设为必填，并切换前台与推荐器。
7. 稳定运行并确认数据完整后，再移除旧自由文本分类和静态推荐数据依赖。

迁移前保留数据库备份或可恢复快照。任一阶段失败均不得删除旧产品资料。

## 11. 错误与生命周期规则

- 不完整产品始终可以保存为草稿。
- 发布校验失败不会修改当前线上版本。
- 品类、模板字段和 SKU 优先停用或归档，避免破坏历史引用。
- 模板新增必填字段前必须先补齐全部已发布产品。
- 配件下线后自动从兼容配件展示中隐藏，但主体产品不受影响。
- 事务失败返回可重试错误，不留下部分 SKU 或部分配件关系。
- 数据库读取失败记录服务端错误；前台不泄露内部数据库或存储信息。

## 12. 测试与验收

### 12.1 自动化测试

- 数据库迁移、内置品类和模板种子测试。
- 品类新增、编辑、排序、归档、受保护字段和必填字段启用规则测试。
- 产品草稿、发布、下线、并发冲突和事务回滚测试。
- SKU 唯一性、默认值继承、价格/链接覆盖和停用测试。
- 英制/公制录入、规范值换算、范围校验、缺失和冲突状态测试。
- 包装内含物排序及兼容配件的角色、自关联、重复和下线测试。
- 电动/手动轮椅承重与有效座宽硬筛选测试。
- 电动/手动轮椅精确适配、排序、无匹配和数据库失败关闭测试。
- 动态商品目录、SKU 切换、详细规格和配件展示测试。
- 普通用户不能访问品类、模板或扩展产品 API 的权限测试。

### 12.2 浏览器验收

1. 管理员创建一个新产品品类及普通规格字段。
2. 管理员创建包含两个 SKU 的电动轮椅，验证默认价格继承与单个 SKU 覆盖。
3. 管理员填写包装内含物并关联两个已发布配件商品。
4. 缺少有效座宽时发布被阻止，并正确定位到 SKU 字段。
5. 补齐资料后发布成功，商品目录无需部署即可出现新产品。
6. 前台切换 SKU 后规格、价格和购买链接正确变化。
7. Wheelchair Finder 可按电动/手动类型筛选，并首先执行承重与有效座宽硬规则。
8. 普通用户看不到后台入口，也不能直接访问新增 API。

## 13. 本期非目标

- 库存数量、仓库和库存扣减
- 站内支付、订单履约和退款
- 按单个 SKU 维护配件兼容性
- Excel 批量导入
- 多管理员角色和审批流
- 代步车、淋浴椅或配件的自动推荐问卷
